## 控制台配置

1. 在 PostgreSQL 的 SQL 编辑器以管理员角色执行 `001_initial.sql`。脚本是单条 DO 语句，可重复执行；创建两个业务表、原子保存函数、私有照片桶和所有者权限。
2. 身份认证 → 登录方式 → 邮箱验证码 → 配置发件邮箱 → 开启邮件代发，并启用该登录方式。
3. 注册配置应允许邮箱注册。首次验证邮箱时自动注册并登录。
4. 当前体验版不能添加自定义 Web 安全域名，GitHub 来源的请求会被网关拒绝。将构建后的 `dist` 部署到环境自带的静态托管域名，该域名已在安全列表中。原 GitHub 页面提供完整备份导出和云端版入口。
5. 登录网站的“设置与备份”，填写邮箱和收到的验证码。首次同步已有两份不同数据时，手动选择保留版本。

两个网址的本机存储独立。已有 GitHub 页面记录，需要在原页面导出完整 JSON，再在云端版导入。若以后升级套餐并给 GitHub 域名添加安全来源，可在 `src/cloudConfig.ts` 中开放该域名。

## 数据保护

本机 IndexedDB 是离线副本。登录后，先保存本机，再延迟上传。断网或上传失败时保留记录，恢复网络和页面焦点时重试；前台每 30 秒检查更新。

`journals` 为当前快照，`journal_versions` 保存最近 50 个成功保存的版本（不是 50 天）。误删后可在云端历史版本中恢复。恢复或用云端替换本机前，额外保留最近 5 份本机保护副本，可导出为 JSON。导入备份也会先保留本机副本。

客户端只有自己的记录和历史版本的读取权限。写入仅允许调用 `save_journal`：服务器从登录令牌读取所有者，在同一事务里校验版本号、更新记录并保存历史。客户端不能直接删除表内记录。不同设备修改同一快照时，暂停同步并请求选择版本。

照片按用户 ID 和内容 SHA-256 保存在私有桶 `meal-photos`。数据库只保存路径；下载后在本机保留完整照片，导出 JSON 仍可独立恢复。历史照片不会随记录删除而删除，便于恢复误删。持续使用时应查看存储用量；目前没有自动清理旧照片。

云同步和同环境历史版本不替代独立备份。建议定期导出 JSON，环境到期、账号丢失或云资源被管理员删除时，仍可从文件恢复。

## 验证

```sh
npm run build
npm test
```

`tests/sync.spec.ts` 验证离线、首次迁移、冲突、换账号、同时编辑与恢复；`tests/database.spec.ts` 在实际 PostgreSQL 引擎 PGlite 中执行迁移并验证 RLS、权限和原子版本校验；`tests/journal.spec.ts` 验证原有本机记录和备份流程。
